

# Part 3 — Create and Send an ICMP Packet

## 1. First understand what you're doing

Normally, when you run:

```bash
ping -c 1 10.6.6.23
```

your operating system automatically creates an ICMP Echo Request.

Here, instead, **Scapy creates the packet manually**.

The packet structure is:

```text
IP
└── ICMP
     └── "This is a test"
```

The command from your lab is:

```python
send(IP(dst="10.6.6.23")/ICMP()/"This is a test")
```

There are three important pieces:

```text
IP(dst="10.6.6.23")
        │
        └── destination IP

ICMP()
        │
        └── ICMP layer

"This is a test"
        │
        └── custom payload
```

The `/` operator in Scapy means:

> **Stack one packet layer on top of another.**

So:

```python
IP(...)/ICMP()/payload
```

means:

```text
IP
 ↓
ICMP
 ↓
Payload
```

# Part 4 — Create and Send a TCP SYN Packet

Now you're moving from:

```text
ICMP
```

to:

```text
TCP
```

The lab uses TCP port:

```text
445
```

Port 445 is commonly associated with **SMB**.

The objective is to observe the response to a TCP SYN directed at that port.

---

# 1. Understand the TCP Three-Way Handshake

Before using Scapy, understand what normally happens.

Suppose:

```text
Kali → Server
```

Kali wants to establish a TCP connection.

The first packet is:

```text
SYN
```

The server responds:

```text
SYN + ACK
```

Then the client sends:

```text
ACK
```

So:

```text
Client                         Server
  │                              │
  │──── SYN ────────────────────>│
  │                              │
  │<──── SYN + ACK ──────────────│
  │                              │
  │──── ACK ────────────────────>│
  │                              │
```

This is the basic TCP three-way handshake.

---

# 2. What is a SYN?

`SYN` means:

> **Synchronize**

It is used to begin TCP connection establishment.

In Scapy, the TCP SYN flag is represented by:

```python
flags="S"
```

# Step 2 — Create the TCP SYN

Go to **Terminal 2**.

Run:

```python
send(IP(dst="10.6.6.23")/TCP(dport=445, flags="S"))
```

Let's break this command down.

## IP layer

```python
IP(dst="10.6.6.23")
```

means:

```text
Destination IP = 10.6.6.23
```

---

## TCP layer

```python
TCP(dport=445)
```

means:

```text
TCP destination port = 445
```

---

## SYN flag

```python
flags="S"
```

means:

```text
TCP SYN flag = set
```

So the complete packet is:

```text
IP
 └── TCP
      ├── Destination port: 445
      └── Flag: SYN
```

The lab describes exactly this packet construction: an IP packet sent to `10.6.6.23`, addressed to TCP port 445, with the SYN flag set. 

---

# 3. What Happens After Sending?

The important part is the **response**.

There are several possibilities.

### Case 1 — SYN + ACK

You might see:

```text
SA
```

That means:

```text
S = SYN
A = ACK
```

This indicates that the target is responding as though the TCP port is **open/listening**.

---

### Case 2 — RST + ACK

You might see:

```text
RA
```

That means:

```text
R = Reset
A = ACK
```

This generally indicates that the TCP connection attempt was rejected and the port is **closed**.

---

### Case 3 — No response

If there is no response, possibilities include:

* Filtering/firewall
* Packet loss
* Host unavailable
* Other network conditions

You shouldn't automatically conclude that the port is closed solely from silence.

# Question — What Does `SA` Mean?

### Answer:

**`SA` means SYN + ACK.**

Breakdown:

```text
S = SYN
A = ACK
```

Therefore:

> **The `SA` flag indicates that the target responded with a TCP SYN-ACK, which is the response expected when the TCP connection request is being accepted. In this lab, that indicates TCP port 445 is open/listening.**

---

# Why Is This Useful?

You have essentially performed the basic logic behind a TCP port check manually.

Instead of using:

```bash
nmap -p445 10.6.6.23
```

you manually created:

```text
TCP SYN → port 445
```

and observed:

```text
SYN + ACK ← port 445
```

The conceptual process is:

```text
                TCP PORT TEST

Kali                         10.6.6.23
 │                                │
 │──── SYN → TCP/445 ────────────>│
 │                                │
 │<──── SYN + ACK ────────────────│
 │                                │
 ▼                                ▼
Port appears                  Port appears
open/listening                to accept TCP
```

This is essentially the packet-level idea behind a TCP SYN scan.

# ICMP vs TCP — Compare Them

This is a very useful way to remember the two exercises.

| Feature           | Part 3                   | Part 4                      |
| ----------------- | ------------------------ | --------------------------- |
| Protocol          | ICMP                     | TCP                         |
| Target            | `10.6.6.23`              | `10.6.6.23`                 |
| Purpose           | Send custom ICMP message | Check TCP port 445 response |
| Scapy layer       | `ICMP()`                 | `TCP()`                     |
| Custom content    | `"This is a test"`       | No custom text payload      |
| Important flag    | ICMP type/code           | `S` = SYN                   |
| Expected response | Echo Reply               | SYN-ACK if accepted         |
| Main lesson       | Packet crafting          | TCP handshake/port state    |
